# Dependency parser memory recovery

Continuation of the authorized Catholic voices/network study. On 28 October,
one 4,380-token sentence exhausted physical memory. The study was stopped,
its closed database and WAL copied together, and 406,828 complete sentences
recovered. No sentence has been skipped or marked complete without a result.

The installed CLASSLA Chu–Liu/Edmonds decoder retains dense score matrices in
its contraction stack. Expansion reads only trees and index mappings, not
those matrices. Test a local adapter that retains only the values expansion
actually consumes. Preserve every numerical operation, order, tie decision,
model, input, rule, transaction and existing execution proof. Do not modify
the installed package or overwrite the preserved parser adapters.

1. Implement a source-hash-guarded compact stack and compare against the
   installed reference on deterministic random, tied and cyclic graphs.
2. Compare complete CLASSLA documents and rule outputs on the same fixed
   2,000 actual standard sentences against original serial inference and
   committed results. Add the largest already completed sentences as stress
   cases. Record hashes, mismatches and timings; this repair is for bounded
   memory, not a new speed claim.
3. Parse the triggering sentence locally with bounded process monitoring.
   Capture exact decoder input scores and check a reference-equivalent
   result where feasible without repeating memory exhaustion. Preserve all
   diagnostics privately. Do not expose corpus text in tool output.
4. Deploy only after parity succeeds, using an additional execution pin and
   a new wrapper. Preserve old pins/proofs; extend the completion audit.
   Resume from recovered commits, restore the report waiter and verify
   checkpoint progress. Keep the original publication gates unchanged.

If equivalence or safe execution cannot be established, retain the failed
qualification and investigate further. Do not truncate, split or silently
exclude the sentence to make the run finish.
