# Barometer validation and candidate audit — 2026-09-18

Read-only review of `R/lib/barometar_validation.R`, `05_validation_draw.R`, the coder template and candidate/boilerplate/classification interfaces against R3 §§3.5–3.6 and 6–7. Source changed concurrently; the findings below describe the inspected implementation and were sent to the implementing agent. No restricted articles, candidate rows or classifications were inspected. Reproductions used invented data in temporary R scripts and an in-memory DuckDB. This report contains aggregate diagnostics only.

## Required before a human evaluation package

1. **Wrong passage offsets after boilerplate masking.** `05_validation_draw.R:28–35` normalizes the unmasked body and applies offsets produced by the classifier from the masked, normalized body. Masked whitespace collapses during normalization, changing every later offset. A synthetic target started at character 28 after masking but at 548 in the unmasked normalized body. Preserve a normalization/raw offset mapping or carry the exact blinded human context from classification; do not apply one coordinate system to another. Human context must still permit review of potentially overmasked evidence.

2. **Only one passage is supplied for multiple article decisions.** `04_classify.R:46–47` takes the first qualifying window. A document sampled for B can therefore show only its unrelated A1 passage. `05_validation_draw.R:32` supplies the first approximately 2,000 characters when a near-miss/recall item has no window, even when its anchors occur much later. Export all relevant, deduplicated passages and one paragraph of actual context per passage, without automatic labels. Choose deterministic anchor-bearing contexts for rejected probes. Fixed ±800 characters are not necessarily one paragraph. Title-only evidence currently supplies no body paragraph.

3. **AI-read exclusions are not enforced.** `barometar_validation_draw()` only filters `development` at line 22; `05_validation_draw.R` never reads `agent_reads.csv`. Explicitly anti-join every logged item, validate log identifiers, and record the exclusion-log digest with the draw. Even if the current reading helper only permits development items, this is an independent required guard.

4. **The near-miss frame does not mean “fails exactly one condition.”** `barometar_engine.R:284` counts three of four whole-document booleans. It excludes documents with all lexical ingredients that fail only proximity, attribution or argumentative linkage, and does not represent B-specific failures. Produce route/window-level condition diagnostics and define the frame from exactly one failed required condition. The recall frame at lines 279–286 uses already masked, capped valid hits and only `concept_families.yaml`; document its scope and include every approved concept family. It cannot independently reveal evidence lost through masking.

5. **The zero-true-evidence-masked check is missing.** R3 §3.5.9 requires this check on validation. The current coding schema and scorer have no mask-review variable or procedure. Preserve unmasked human context for relevant masked segments, collect the human decision without revealing automated route classifications, and enforce zero confirmed losses before release.

## Scoring correctness

6. **Per-route point precision and gate ignore unequal sampling probabilities.** Lines 34–39 deliberately balance pre/post batches; lines 85–90 then use pooled `k/n`. A synthetic route containing 90 correct pre-seam and 10 incorrect post-seam articles has population precision 0.90. The implementation samples 30 + 10, reports 0.75 and labels the route experimental. Weight stratum estimates by route population shares, and use an interval appropriate to the stratified design. Ordinary pooled Wilson describes the disproportionate sample, not population route precision. Preserve raw `n`, `k` and stratum Wilson diagnostics transparently rather than labelling a weighted estimate as an ordinary binomial Wilson result.

7. **Short strata waste the requested sample.** The same test draws 40 instead of 60 despite a 100-item frame. Allocate the short stratum's unused quota to the other available stratum, while retaining half/half where feasible and recording actual probabilities. Deduplicating overlapping route draws is correct; actual unique burden should be reported rather than forced to 430.

8. **A2 and A? are scored with impossible inclusion semantics.** Line 87 requires both `qualifies == da` and the sampled route in the human construct set. All 25 correctly coded A2-only items (`ne`, `A2`) received zero precision. All 25 A? items adjudicated to A1 also received zero because the coder cannot select A?. A2 needs label-classification accuracy independent of inclusion; A? needs its human resolution distribution and false-negative diagnostics. D remains an attribution diagnostic under the approved D4 choice. None of A2/A?/D should become an inclusion route because of an “accepted” table label.

9. **Construct agreement hides disagreements.** Lines 77–83 collapse multi-label construct sets by A1/B/C/A2/D priority. A synthetic second coder omitted every D label from `A1;D` items yet construct κ remained 1. Compare normalized sets as categories and/or report per-label agreement. If a primary construct is desired, collect it explicitly instead of silently discarding human labels.

10. **Required validation outputs are incomplete.** The scorer emits route rows and broad precision, but no per-batch estimates, theme precision/status, near-miss or recall-frame miss diagnostics, adjudication log, or explicit A1-only/no-publication fallback result. Broad precision currently uses all A1/B/C route sets before route-specific acceptance. The final publishable union must use the accepted routes, and fallback/card decisions must be explicit. The caller must validate coding-file definition/draw IDs and log PI adjudications after independent coding. `06_validation_score.R` was absent at inspection.

11. **Human label schema is only partly validated.** `barometar_validate_coding()` checks IDs, coder type, completeness and `qualifies`, but not allowed values or contradictory construct sets for other fields. The template also departs from the referenced CODEBOOK: Axis 3 omits `both`; Axis 4 collapses the two `object_*` codes and omits `other`. Restore the source codes or document and ratify an explicit collapsed crosswalk, then reject invalid labels before scoring. Keep “ništa” exclusive.

The existing blinding is useful: HTML payloads contain item ID, date, outlet and passage, without automated routes, rule IDs, matches, batch or facets. PI and second-coder packages use separate storage keys and the second-coder assignment is random. Broad route-set weighting includes union inclusion probabilities across overlapping draws; that part correctly accounts for differing chances of appearing in the deduplicated coding set, assuming the component draws are independent.

## Candidate and boilerplate checks

12. **Empirical superset proof is not implemented in the inspected pipeline.** The loader verifies literal coverage and normalization-recovery arms. Tests include useful invented ICU/RE2 perturbations. However, no code was found drawing 20,000 seeded prefilter-rejected panel representatives per batch and requiring zero anchor hits; the loader correctly leaves `empirical_rejected_rows_verified=FALSE`. R3 makes this a hard gate. Run locally with only aggregate results exposed. Anchor-only retrieval is logically sufficient for current routes if each route's mandatory-anchor invariant is asserted; the current static coverage tests apply only to the supplied anchor subset, not to that route invariant itself.

13. **SQL/R boilerplate inputs differ at title prefixes.** SQL segments `FULL_TEXT`; R first removes an exact leading title and punctuation and then segments the body. A synthetic repeated first segment whose SQL key includes the title produces `masked_chars=0` in R. Apply the same body preparation to both producers, or preserve full-text segment coordinates and reconcile the removed title explicitly. Add the equivalence fixture at this interface, not only at the string-key helper.

14. **SQL/R Unicode lowercasing can give different keys.** An in-memory test using the current SQL expression and `barometar_boilerplate_key_text()` produced equality results `FALSE, TRUE, TRUE` for Greek final sigma, dotted I and a Croatian whitespace/digit control. ICU performs contextual final-sigma casing; DuckDB's lowercase result differs. Use one explicitly shared casing contract or materialize keys with one implementation, and test this Unicode edge case. This is a verified mismatch, not a claim about its observed frequency in source data.

15. **Classification cache identity remains incomplete.** During review, root improved candidate cache identity to input digest + panel + prefilter + transport contract, and boilerplate identity to include input/panel/trigger. Those changes address the initial stale-cache concerns in `03_candidates.R`. `04_classify.R` still names its cache directory with definition/engine/development-mode only and reuses an existing monthly file immediately. A changed input digest, panel or boilerplate table can therefore reuse old classification content despite validating the current manifests. Include all three in cache identity and stored metadata. Validate classification and candidate manifests against the same panel/input/definition when drawing.

## Reproductions completed

All synthetic probes completed successfully as demonstrations of the findings: unequal-batch gate mismatch, quota shortfall, A2/A? zero scores, hidden D disagreement, normalized-offset mismatch, SQL/R Unicode-key mismatch and title-prefix mask mismatch. Startup reported the existing inherited C.UTF-8 locale warnings and renv status notice; no probe failed to execute. Source changes and regression tests remain with the implementing agent.
